## 0. 一句话结论

Readio M1 的 UI 不是“做一个功能很多的阅读器”，而是把 **导入一本书、立刻开始读、稳定继续读** 这三件事做到足够顺滑。

因此 M1 的交互设计必须服务三个核心目标：

1. **导入成本低**：用户第一次打开后，能快速理解如何把本地书导入进来。
2. **继续阅读优先**：每次回到 App，界面都优先帮助用户回到上次阅读位置，而不是重新做选择。
3. **正文高于界面**：阅读页里 UI 退后，内容上前，设置与控制都只在需要时出现。

---

## 1. 设计背景与北极星

### 1.1 当前 M1 范围

M1 只覆盖本地阅读闭环：

- 本地导入
- 书架
- 继续阅读
- EPUB / TXT 主阅读体验
- PDF 有界兼容
- 基础阅读设置
- 文件失效 / 权限失效恢复

明确不进入 M1 阻塞范围：

- AI 阅读助手
- 搜书发现
- 账号 / 同步
- 社区
- 深度 PDF 能力

### 1.2 设计北极星

Readio M1 的页面设计必须始终回答这个问题：

> 用户打开 App 后，是否能在最短路径内重新进入上次那本书？

只要某个 UI 决策削弱了这条路径，就不该进入 M1。

### 1.3 体验目标

- 首次使用者应在 **30 秒内** 理解主路径：导入书 → 开始读
- 回访用户应在 **3 秒内** 找到并点击“继续阅读”
- 阅读页应尽可能减少非正文噪音，让用户把注意力留给内容

## 2. 设计原则

### 2.1 继续阅读优先于书库管理

书架首页首先服务“继续读”，其次才是“管理我有多少书”。

### 2.2 正文优先于控制层

阅读页默认沉浸，控制层只在用户显式唤起时出现。

### 2.3 异常恢复产品化

导入失败、文件失效、权限失效不能只用技术报错或短暂 toast。必须给用户可理解的解释和下一步动作。

### 2.4 一跳可达高频能力

目录、进度、主题 / 字号等高频能力必须在阅读页一跳可达，不能深埋。

### 2.5 EPUB / TXT 同壳，PDF 同语义不同深度

EPUB / TXT 使用统一阅读产品壳；PDF 共享导入、继续阅读、错误恢复和基础设置语义，但不假装拥有同等级深能力。

### 2.6 M1 只保留必要复杂度

不加入二级书架筛选、不加入重度书籍管理、不加入复杂动画和多套阅读模式。先把主链路打磨顺。

---

## 3. 视觉方向

### 3.1 气质定位

Readio M1 的视觉应接近：

- 安静
- 温和
- 克制
- 有阅读感
- 不带内容社区和运营产品气味

参考方向：

- 阅读连续性借鉴多看式低打扰体验
- 产品结构借鉴现代 Android App 的清晰导航
- 架构与产品思路借鉴 Readest 的“阅读器是核心任务，不是装饰模块”

### 3.2 色彩方向

采用 **暖中性色 + 单一点缀色**，避免工具味纯白，也避免蓝紫渐变 AI 感。

#### 建议色板

- 浅色背景：`#F6F1E8`
- 浅色卡片：`#FFFDF8`
- 主文字：`#1F1B16`
- 次文字：`#6B6257`
- 分割线：`#E6DED2`
- 点缀色：`#C96F3B`
- 深色背景：`#171411`
- 深色卡片：`#211C18`
- 深色主文字：`#F3EBDD`
- 深色次文字：`#B8AEA1`

### 3.3 字体与层级

M1 不强推品牌字体，优先使用 Android 现成字体体系，通过层级和留白建立产品气质。

- 页面标题：SemiBold
- 书名 / 关键 CTA：Medium / SemiBold
- 辅助信息：Regular
- Reader 正文：由内容渲染体系控制，UI 字体不抢正文注意力

### 3.4 圆角、阴影、分隔

- 卡片圆角：中等，不走满屏大圆角玩具感
- 阴影：极弱，更多依赖底色区分层级
- 分隔：优先用间距，其次再用淡分割线

### 3.5 动效原则

- 默认轻量
- 只服务状态切换理解
- 不做装饰性动画
- 阅读页控制层显隐要快，不能拖泥带水

## 4. 一级信息架构

### 4.1 一级导航

M1 只保留两个一级入口：

- **书架**
- **设置**

阅读页不进入一级导航，它是任务页，不是栏目页。

### 4.2 结构示意

```text
[书架]      [设置]
   |            |
   |            └─ 应用设置 / 阅读默认项 / 关于
   |
   ├─ 继续阅读卡
   ├─ 全部书籍
   ├─ 导入
   └─ 点击书籍 -> Reader
                    ├─ 目录抽屉
                    ├─ 阅读设置 Sheet
                    └─ 文件恢复交互
```

### 4.3 导航原则

- 用户从书架进入阅读页后，不再需要看到底部导航
- 阅读页返回后回到书架原位置
- 外部 `ACTION_VIEW` / `ACTION_SEND` 进入时，如果导入成功，直接落到阅读页

## 5. 页面与交互规范

## 5.1 书架首页

### 页面目标

让用户一眼看见“我该点哪里继续读”。

### 布局结构

书架首页首屏必须明确分成三种状态，而不是只有“有书 / 没书”两种：

1. **无书**：显示空状态，引导导入第一本书。
2. **有书但无阅读历史**：顶部显示“开始阅读你的第一本书”引导区，展示最近导入或最近添加的一本书，主 CTA 为 `开始阅读`。
3. **有阅读历史**：顶部显示继续阅读卡，作为首页最高优先级动作。

#### 顶部栏
- 左：页面标题 `书架`
- 右：导入按钮 `导入`

导入按钮保留文字，不只用 icon，降低首次使用理解成本。

#### 继续阅读卡
位于页面最上方，视觉优先级高于书籍网格。

**卡片信息：**
- 封面
- 书名
- 作者（可选）
- 恢复提示
  - EPUB：`已恢复到：第二章`
  - TXT：`已恢复到：63%`
  - PDF：`已恢复到：第 8 页`
- 主 CTA：`继续阅读`

**交互要求：**
- 整卡可点
- CTA 可点
- 点击后优先恢复到最近可信位置

#### 全部书籍区
位于顶部主引导区下方，属于次级浏览区。

**布局：**
- 手机默认 2 列网格
- 每项显示：封面、书名、作者或格式辅助信息
- 长书名最多两行，超出截断
- 首屏默认露出 4-6 本，避免和顶部主动作争夺注意力

**层级要求：**
- 顶部主引导区始终是首屏第一视觉焦点
- `全部书籍` 或 `你的书` 作为次级标题，不与继续阅读主卡同权呈现

**为什么用 2 列：**
- 比列表更像阅读产品
- 比 3 列更容易保持封面存在感和书名可读性

### 空书架状态

当没有任何书时，显示空状态而不是空白网格。

**文案结构：**
- 主标题：`把你的书导进来`
- 说明：`支持 EPUB、TXT，PDF 可基础阅读`
- 主按钮：`导入本地书籍`
- 次说明：`导入成功后会自动开始阅读`

### 线框草图

```text
[书架]                         [导入]

┌──────────────────────────────┐
│ 继续阅读                      │
│ [封面]  三体                 │
│        已恢复到：第 12 章     │
│        [继续阅读]            │
└──────────────────────────────┘

全部书籍

[封面] 三体        [封面] 庆余年
作者 / EPUB        作者 / TXT

[封面] 雪中悍刀行   [封面] 活着
作者 / EPUB        作者 / PDF

[书架]                      [设置]
```

## 5.2 导入交互

### 导入入口

M1 共有三种导入入口：

1. 书架页右上角 `导入`
2. 空状态主按钮 `导入本地书籍`
3. 外部系统导入：`ACTION_VIEW` / `ACTION_SEND`

### 导入流程规则

导入流程采用三段式反馈，而不是“点导入后直接跳 Reader”：

1. 用户选中文件后，进入轻量 loading 状态：`正在导入《书名》...`
2. 导入成功后自动进入阅读页
3. 进入阅读页后显示一次性轻提示：`已打开《书名》`

补充要求：
- 不建立复杂“导入中心”页面
- 导入只是进入阅读的前置动作，不应打断主路径
- loading 应优先挂在页面级轻遮罩或局部全局状态，而不是只让按钮进入 loading
- loading 期间仍保留返回能力，避免用户误以为应用卡死

### 导入状态反馈

#### loading
- 页面进入轻量导入中状态：`正在导入《书名》...`
- 不阻塞整个应用到不可返回
- 不允许只有按钮级 loading 而没有页面级状态提示

#### 成功
- 自动进入阅读页
- 首次打开显示轻提示：`已打开《书名》`
- 若导入来源是外部 `ACTION_VIEW` / `ACTION_SEND`，同样沿用这套反馈，避免用户感到被突然跳页

#### 失败
- 不能只用 toast
- 必须给清楚原因 + 下一步动作
- 失败原因至少区分以下三类：
  - 格式不支持
  - 权限失效 / 文件无法访问
  - 文件损坏或解析失败

**推荐文案：**
- `这本书当前无法打开`
- `文件权限已失效，请重新选择原文件`
- `暂时不支持这个文件格式`
- `文件可能已损坏，或暂时无法解析`

## 5.3 阅读页

### 页面目标

让用户感到“界面退后，内容上前”。

### 默认状态：沉浸态

进入阅读页后默认隐藏大部分控制元素：

- 顶部栏隐藏
- 底部栏隐藏
- 正文全屏优先
- 仅保留极轻的进度信息

### 轻量常驻信息

可在底部保留低存在感阅读信息：

- 当前章节 / 页码
- 阅读百分比
- 必要时显示短提示

信息必须轻，不得抢正文视觉。

### 控制层唤起规则

默认规则：**单击正文** 显示 / 隐藏控制层。

但 M1 必须补齐阅读页状态机，避免实现时各写各的。最少包含以下状态：

- `沉浸态`
- `控制态`
- `目录展开`
- `阅读设置 Sheet 展开`
- `恢复提示显示中`

#### 状态规则
- 进入阅读页默认进入 `沉浸态`
- 单击正文：`沉浸态 <-> 控制态`
- 控制态显示后，若用户在 2-3 秒内无后续操作，可自动回到沉浸态
- 若目录或设置面板已展开，不再触发主控制层自动隐藏竞争
- 关闭目录 / 设置面板后，回到 `控制态`，而不是直接跳回 `沉浸态`
- 恢复提示优先级低于目录 / 设置，但高于常驻轻进度信息

#### PDF 特殊规则
- PDF 中的缩放、拖拽优先于控制层唤起
- 仅当用户单击空白区域或非手势冲突区域时，才切换控制层
- 不允许缩放手势误触发控制层显隐

#### 无障碍兜底规则
- 当 TalkBack 或其他屏幕阅读器开启时，不能只依赖“单击正文”作为唯一入口
- 必须提供始终可聚焦、可命名的显式控件，例如：`显示阅读控制`
- 控制层打开后，焦点优先落到顶部标题或底栏第一个操作；关闭后返回触发控件

### 控制态结构

#### 顶部栏
- 返回
- 书名
- 可选：更多入口（M1 可后置）

#### 底部栏
M1 只保留三个高频入口：
- `目录`
- `进度`
- `设置`

不建议在 M1 增加更多底栏按钮，否则会冲淡阅读主任务。

### 线框草图

#### 沉浸态

```text
┌──────────────────────────────┐
│                              │
│        正文内容正文内容       │
│        正文内容正文内容       │
│        正文内容正文内容       │
│                              │
│                     第12章 43%│
└──────────────────────────────┘
```

#### 控制态

```text
┌──────────────────────────────┐
│ < 返回      三体             │
│──────────────────────────────│
│                              │
│        正文内容正文内容       │
│                              │
│──────────────────────────────│
│ 目录        进度       设置   │
└──────────────────────────────┘
```

## 5.4 EPUB / TXT / PDF 的呈现策略

### EPUB / TXT

共享同一套阅读产品壳：

- 相同阅读页结构
- 相同设置入口
- 相同目录与恢复语义
- 相同错误恢复语言

### PDF

共享产品语义，但不强做深统一。

M1 对 PDF 只承诺：
- 可导入
- 可打开
- 可翻页 / 缩放
- 可记录并恢复页码

面向用户的统一表达固定为：

> `支持 PDF 基础阅读，可翻页、缩放与继续阅读。`

这句文案应在以下场景保持一致：
- 书架空状态说明
- 设置页支持格式说明
- 首次打开 PDF 时的轻提示或帮助说明

因此 PDF 页面允许与 EPUB / TXT 在内容区交互上不同，但外层壳必须尽量一致：
- 同样从书架进入
- 同样支持继续阅读
- 同样在打开失败时给出恢复动作
- 不支持的 EPUB/TXT 深能力不应以灰态控件形式堆在 PDF 页面上，直接不出现更清楚

## 5.5 恢复交互

### 设计目标

恢复必须让用户“感知到成功”，而不是默默跳转后让人怀疑位置为什么变了。

### 成功恢复

进入阅读页时显示短提示：

- `已恢复到上次阅读位置`
- 如果有更具体结构信息，可显示：`已恢复到：第二章`
- PDF 可显示：`已恢复到：第 8 页`

### 恢复降级

当不能精确恢复时，不应静默失败。

**推荐提示：**
- `未能精确恢复，已为你打开最近可用位置`
- `原位置不可用，已从本章开头继续`

### 语义要求

- EPUB：可信位置恢复，不夸大成精确中途重建
- TXT：章节 + 进度优先，漂移后回退到全文线性位置
- PDF：页码优先，失败则回退最近合法页

---

## 5.6 目录

### 形态

推荐使用 **侧边抽屉**，而不是单纯底部面板。

### 原因

- 目录本质上是结构导航，不是简单参数设置
- 侧边抽屉更适合长列表扫描
- 更接近“正文旁展开结构层”的感受

### 目录内容

- 标题：`目录`
- 辅助信息：`共 32 章`
- 列表项：章节标题
- 当前章节：高亮
- 点击章节：立即跳转并关闭抽屉

### 交互与可访问性契约

目录抽屉在 M1 中按模态层处理：
- 打开时，TalkBack 优先朗读标题，例如：`目录，共 32 章`
- 抽屉打开时，背景正文不应继续作为可访问焦点目标
- 关闭方式至少包括：显式关闭按钮、系统返回键
- 关闭后，焦点返回到触发目录的按钮
- 章节跳转后应有结果播报，例如：`已跳转到第二章`

### 目录项原则

- 整行可点
- 标题过长允许两行截断
- 不引入复杂已读统计
- 不加入花哨层级装饰

---

## 5.7 阅读设置面板

### 形态

使用 **底部 Sheet**。

### 原因

- 高频、轻量、临时操作适合从底部快速拉起
- 不必离开正文上下文

### M1 必须项

#### 主题
- 浅色
- 深色
- 护眼

#### 字号
- `A-` / `A+`
- 中间用 slider 或 stepper

#### 行距
- 紧凑
- 标准
- 宽松

#### 亮度
- 可调 slider
- 若系统限制明显，可标记为设备亮度

### M1 不做深度项

- 多字体切换
- 复杂页边距调节
- 多种翻页动画
- 高级排版参数矩阵

### 面板要求

- 优先在一屏内完成绝大多数操作，但不能为了一屏塞下而牺牲大字号可读性
- 交互要即时反馈
- 变更后立刻作用到正文

### 可访问性契约

阅读设置 Sheet 在 M1 中按模态层处理：
- 打开时优先朗读标题 `阅读设置`
- 关闭方式至少包括：显式关闭按钮、系统返回键
- 关闭后焦点返回到触发设置的按钮
- slider、stepper、主题选项都必须有明确无障碍语义，能读出当前值与可执行动作
- 模态层打开时，背景正文不应继续作为可访问焦点目标

## 5.8 设置页

### 页面定位

设置页在 M1 中不是主战场，作用是承载低频项，避免阅读页过重。

### 建议结构

#### 分组一：阅读
- 默认主题
- 是否保持屏幕常亮
- 是否跟随系统夜间模式

#### 分组二：导入与文件
- 文件访问说明

## 5.9 文件失效 / 权限失效恢复

### 场景

- 原文件被删除
- 原文件被移动
- URI 权限失效
- 外部存储不可访问

### 设计要求

不能只弹一句 toast 再失败返回。

### 推荐交互

使用阻断式恢复页或明确对话层。

恢复交互至少分成两类：

1. **可直接重试型**：例如临时访问失败，优先给 `重试`
2. **必须重新定位型**：例如文件移动、删除、权限失效，给 `重新选择原文件`

**通用标题：**
`这本书暂时找不到了`

**说明：**
`可能是原文件被移动、删除，或者访问权限失效。`

当原因可明确判断时，应使用更具体文案：
- `文件权限已失效，请重新选择原文件`
- `原文件可能已被移动或删除，请重新定位`

**操作：**
- 主按钮：`重新选择原文件`
- 次按钮：`返回书架`
- 可直接重试型场景可增加：`重试`

### 恢复成功后的要求

- 尽量保留当前书籍身份
- 尽量沿用已有阅读进度
- 成功后直接回到阅读页，而不是让用户重新找书
- 恢复成功后要给确认闭环，例如：`已重新连接《书名》`、`已恢复到上次阅读位置`

### 恢复失败后的保底出口

- `重新选择其他文件`
- `返回书架`
- 如后续产品允许，可补 `移出书架`

### 线框草图

```text
这本书暂时找不到了

可能是原文件被移动、删除，
或者访问权限失效。

[重新选择原文件]
[返回书架]
```

## 6. 关键用户流

## 6.1 首次使用

1. 打开 App
2. 看到空书架
3. 点击 `导入本地书籍`
4. 选择 EPUB / TXT / PDF
5. 导入成功
6. 自动进入阅读页
7. 显示轻提示：已打开 / 已恢复到起始位置

**成功标准：**
用户在 30 秒内理解产品主路径。

## 6.2 日常继续阅读

1. 打开 App
2. 顶部看到继续阅读卡
3. 点击 `继续阅读`
4. 进入 Reader
5. 恢复到最近可信位置

**成功标准：**
用户在 3 秒内回到书里。

## 6.3 从书架切换到别的书

1. 打开 App
2. 在全部书籍中选择一本
3. 进入阅读页
4. 有进度则恢复，无进度则从起始位置打开

## 6.4 文件失效恢复

1. 用户点击某本书
2. 系统发现源不可用
3. 展示恢复交互
4. 用户重新选择原文件
5. 系统重新建立可用来源
6. 尽量恢复到原阅读位置

## 7. 文案规范

### 7.1 文案风格

- 用户语言，不用技术术语
- 短句
- 明确下一步
- 不做“系统报错翻译腔”

### 7.2 推荐文案

所有异常与恢复文案统一遵循三段式：
1. 发生了什么
2. 系统当前帮用户做了什么，或没做到什么
3. 用户下一步可以做什么

#### 书架空状态
- `把你的书导进来`
- `支持 EPUB、TXT，支持 PDF 基础阅读，可翻页、缩放与继续阅读`
- `导入本地书籍`

#### 继续阅读
- `继续阅读`
- `已恢复到：第二章`
- `已恢复到：63%`
- `已恢复到：第 8 页`

#### 导入失败
- `这本书当前无法打开`
- `请重新选择文件，或换一个受支持的格式`
- `文件可能已损坏，或暂时无法解析，请重新选择文件再试一次`

#### 文件失效
- `这本书暂时找不到了`
- `原文件可能已被移动、删除，或者访问权限失效`
- `请重新选择这本书当前所在的文件`
- `重新选择原文件`
- `返回书架`

#### 恢复降级
- `没能回到上次停下的精确位置，已先打开最近可用位置。你可以从目录继续找回原进度。`

## 8. 可访问性与设备适配

### 8.1 可访问性基线

- 所有点击目标最小尺寸满足 Android 可触达要求
- 文本与背景对比度满足深浅主题下可读性要求
- Reader 设置中的字号调节必须真正影响正文可读性
- 控制层 icon 必须有文字或可被无障碍识别的语义标签
- 正文与主要文本对比度至少满足 4.5:1；大号粗体文本可按 3:1 处理，但不得误把普通辅助文案当作大文本放宽要求
- 关键控件边界、选中态、slider 轨道 / 拇指、焦点态应满足非文本对比要求

### 8.2 Reader 无障碍重点

- 单击唤起控制层不能让读者丢失当前阅读上下文
- 当 TalkBack 开启时，必须提供显式且可聚焦的 `显示阅读控制` 入口，不能只依赖点击正文
- 目录抽屉列表项必须整行可点
- 继续阅读卡必须对 TalkBack 明确表达书名与恢复信息
- 控制层打开后的焦点顺序必须稳定，关闭后回到原触发控件

### 8.3 设备适配

M1 主目标是 Android 手机，但布局要避免写死到只适配单一窄屏：

- 书架网格需根据窗口宽度自适应列数
- 目录抽屉和设置面板在大屏上可适度放宽
- 不让底栏、标题栏在大字体模式下挤压失真
- Android 最大系统字体档位下，不允许出现关键文字不可理解截断、控件重叠、必须双向滚动才能完成主要操作
- Reader 底栏在大字号下允许增高或两行布局，但不得把关键入口挤没
- 继续阅读卡在大字号下优先保留书名与主 CTA，恢复信息可换行但不能把 CTA 挤出首屏

## 9. 设计验收清单

### 9.1 书架
- [ ] 用户第一次打开就知道如何导入
- [ ] 继续阅读入口在首页最高优先级
- [ ] 全部书籍区能快速定位其他书

- [ ] UI 不像内容社区

## 10. M1 不进入的设计项

- 云同步入口
- 社交阅读模块

- 复杂翻页模式矩阵

## 11. 与实现计划的对齐要求

这份设计方案对 M1 implementation plan 施加以下约束：

1. `书架` 必须是默认首页，不保留 M0 spike 首页逻辑。
2. 导入成功后必须支持自动开读，而不是停在书架等待二次点击。
3. `继续阅读` 的语义必须基于最近有效阅读进度，而不是最新导入书。
4. Reader 必须实现“沉浸态 / 控制态”双状态切换。
5. 目录必须作为清晰可达的结构入口，不可降级为隐蔽测试按钮。
6. 文件失效 / 权限失效必须进入产品化恢复交互，不可只打印错误。
7. PDF 页面虽然是有界兼容，但外层产品语言必须与 EPUB / TXT 一致。

## 12. 最终建议

Readio M1 最合适的方向是：

> **暖色极简 + 继续阅读强优先 + Reader 极简沉浸 + 恢复交互产品化**

这条路线的好处是：

- 它和 Readio 当前“本地阅读闭环”的目标完全一致
- 它不会把资源浪费在 M1 不关键的炫技层
- 它能把用户最在意的“顺滑继续读”做成真正的产品感

## 1. 产品身份冻结

### 1.1 Readio 是什么

Readio 是一个 **Android-first、纯本地、面向小说场景的沉浸式阅读 App**。

当前阶段的核心价值只有两件事：

1. 用户能把自己已有的书顺滑导入并开始阅读
2. 用户能稳定回到上次阅读位置并持续读下去

### 1.2 Readio 不是什么

当前阶段明确不是：

- 书城
- 内容托管/下载平台
- 社区产品
- 万能文档工具
- 独立聊天型 AI 产品
- 多端同步平台

---

## 2. 当前正式开发范围冻结

### 2.1 正式开发默认只覆盖 M1

M1 只负责：

- 本地导入
- 书架
- 继续阅读
- EPUB / TXT 主阅读体验
- PDF 基础兼容
- 阅读设置最小集
- 稳定性与恢复链路

### 2.2 明确不让这些阻塞 M1

以下能力保留在长期产品方向，但不构成当前正式开发阻塞项：

- AI 阅读助手
- 搜书发现与外跳
- 云同步
- 账号体系
- 社区
- 重度知识管理
- 深度 PDF 能力

---

## 3. M1 成功标准冻结

M1 的成功不是“功能看起来很多”，而是本地阅读闭环成立。

### 3.1 用户体验成功标准

- 用户能在 **3 分钟内导入一本书并开始阅读**
- 用户重新打开 App 后，能稳定回到上次阅读位置
- 用户第一次使用时，能迅速理解“导入书 → 开始读 → 继续读”的主路径

### 3.2 产品北极星指标（当前阶段）

正式开发前，默认以以下指标作为 M1 主指标候选：

1. **周阅读时长**
2. **继续阅读回访率**
3. **7 日留存**

进入 M1 implementation plan 时，必须从以上三项中明确主指标与次指标，不能空缺。

## 4. 格式边界冻结

### 4.1 EPUB

- 主路径
- M1 重点支持对象
- 目标：稳定打开、目录可用、位置恢复可靠

### 4.2 TXT

- 主路径
- 通过轻量章节识别进入统一文本阅读模型
- 解析失败时必须可降级到“全文线性阅读”

### 4.3 PDF

- 兼容路径
- M1 仅承诺：
  - 可导入
  - 可打开
  - 可翻页/缩放
  - 可记录并恢复页码位置
- M1 明确不承诺：
  - reflow
  - 复杂标注
  - 与 EPUB/TXT 同等级阅读体验

## 5. 正式技术栈冻结

### 5.1 客户端栈

- Kotlin
- Jetpack Compose
- Navigation Compose
- ViewModel + StateFlow
- Coroutines

### 5.2 数据与状态

- Room：书籍索引、阅读进度、书签、基础元数据
- DataStore：阅读设置与轻量偏好

### 5.3 阅读能力

- EPUB：Readium Kotlin Toolkit
- TXT：自建轻量解析层
- PDF：Android PdfRenderer

### 5.4 工程形态

- 单 Android App
- 模块化单体
- 不走 Web/Tauri/跨平台 runtime
- 不以 Readest 作为直接代码基础

---

## 6. 开源基座取舍冻结

### 6.1 Readest 的定位

Readest 只作为：

- 模块拆分参考
- 阅读器能力地图参考
- 状态与持久化分层参考

### 6.2 明确不采用 Readest 作为直接底座

原因：

- 技术栈不匹配（Next.js + Tauri + Rust）
- 工程目标不匹配（跨平台 vs Android-first）
- 产品复杂度不匹配（同步/云/AI/支付过重）

结论：

> **借鉴 Readest 的架构思想，不借它的技术底座。**

## 7. UI / 交互基线冻结

### 7.1 参考对象

Readio 的阅读器交互与 UI 方向，以“多看式低打扰、高连续性阅读体验”为强参考。

### 7.2 M1 必须锁定的 UX 规则

- 书架首页优先服务“继续阅读”
- 阅读页默认极简，全屏沉浸
- 单击正文显示/隐藏控制层
- 高频设置一跳可达：目录、字号、主题/夜间、亮度、进度
- 复杂设置进入二级阅读设置页
- 目录优先采用抽屉式/侧滑式
- 进度信息轻量常驻，不打断正文

### 7.3 M1 必须先拍板的交互决策

进入 M1 implementation plan 前，必须明确：

1. 阅读主交互形态：**滚动优先** 或 翻页优先
2. 控制层显示/隐藏规则
3. 进度保存与恢复语义
4. 错误恢复交互：文件失效、权限失效、导入失败

默认建议：

- **滚动优先**
- 翻页模式后置，或仅保留极少数稳定模式

## 8. 商用边界冻结

Readio 具备商用潜力，但必须建立在合规、本地阅读效率价值之上。

### 8.1 可商业化价值

- 本地导入后快速开读
- 长时间沉浸阅读体验
- 稳定的继续阅读能力
- 后续防剧透 AI 辅读能力

### 8.2 必须保护的边界

- 不托管未经授权内容
- 不做未授权内容下载闭环
- 不把搜书定义为产品主身份
- 不把增长建立在灰色内容链路上
- AI 默认不得越过阅读边界

结论：

> **Readio 可以商业化，但前提是它始终是“合规的本地阅读效率工具”，而不是内容捷径工具。**
